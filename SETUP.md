# Getting Started on Mac

This document explains how to install, clone, organise, run, edit and synchronise the BIIGLE Benthic Image Analysis Pipeline from a Mac.

The central principle is simple:

> **Work locally. Use GitHub as the remote, versioned and shareable record of the project.**

You should normally have one permanent local copy of the repository on your Mac. Do not create a new copy in `Downloads/` every time the project changes.

---

# 1. Recommended local location

The recommended location is:

```text
~/Documents/GitHub/BIIGLE-Benthic-Pipeline/
```

In Finder this corresponds approximately to:

```text
Macintosh HD
└── Users
    └── <your-user-name>
        └── Documents
            └── GitHub
                └── BIIGLE-Benthic-Pipeline
```

Create the parent folder once:

```bash
mkdir -p ~/Documents/GitHub
```

Move into it:

```bash
cd ~/Documents/GitHub
```

Check your location at any time with:

```bash
pwd
```

## Folder roles

| Folder | Purpose | Normally edited manually? | Git-tracked? |
|---|---|:---:|:---:|
| `Raw/` | Original BIIGLE exports and provenance archives | No | No, except documentation/placeholders |
| `Sheets/` | Canonical prerequisite input tables | Yes, deliberately | Yes for the worked example |
| `Scripts/` | Bash/R processing and analysis code | Yes | Yes |
| `Data/Intermediate/` | Numbered transformed datasets | No; generated | Selected worked-example outputs may be tracked |
| `Data/Final/` | Stable point and VME analytical datasets | No; generated | Selected worked-example outputs may be tracked |
| `Analyses/` | Statistical tables, diagnostics and model outputs | No; generated | Yes when part of the worked example |
| `Figures/` | Numbered figures generated by scripts | No; generated | Yes when part of the worked example |

> [!IMPORTANT]
> Do not rename folders casually. Scripts and README links will use these relative paths.

# 3. Install the basic Mac tools

## 3.1 Terminal

macOS includes Terminal. Open:

```text
Applications > Utilities > Terminal
```

## 3.2 Git

Check whether Git is available:

```bash
git --version
```

If macOS prompts you to install Command Line Developer Tools, accept the installation and then rerun:

```bash
git --version
```

## 3.3 Configure your Git identity

You normally do this once per computer:

```bash
git config --global user.name "Your Name"
git config --global user.email "YOUR_GITHUB_EMAIL"
```

Check the settings:

```bash
git config --global --list
```

## 3.4 R

Check whether R is installed:

```bash
R --version
```

Check whether `Rscript` is available:

```bash
Rscript --version
```

Install the required analysis packages once:

```bash
Rscript Scripts/install_R_packages.R
```

RStudio is optional: it is useful for editing and interactive exploration, but the formal scripts are designed to remain runnable from Terminal using `Rscript`. Package versions will be locked once the analysis suite has completed runtime validation.

## 3.5 GitHub authentication

You can use Git over HTTPS or SSH. GitHub CLI is convenient but not required.

If GitHub CLI is installed:

```bash
gh --version
```

Authenticate with:

```bash
gh auth login
```

Check authentication with:

```bash
gh auth status
```

# 7. What belongs in Raw/

`Raw/` is for local provenance material such as:

```text
Raw/
├── BIIGLE_export_01.zip
├── BIIGLE_export_02.zip
├── BIIGLE_export_03.zip
└── ...
```

These files are intentionally ignored by Git through `.gitignore`.

The pipeline currently assumes that the raw BIIGLE ZIP/CSV exports are manually concatenated before formal processing begins.

Therefore:

```text
Raw BIIGLE exports
        |
        | manual concatenation
        v
Sheets/combined_biigle_annotations.csv
        |
        | formal reproducible pipeline begins here
        v
Data/Intermediate/
```

Do not depend on `Raw/` files from within formal analysis scripts.

# 9. Where to run scripts from

Unless a script explicitly says otherwise, run pipeline commands from the repository root:

```bash
cd ~/Documents/GitHub/BIIGLE-Benthic-Pipeline
```

This is important because scripts will increasingly use relative paths such as:

```text
Sheets/...
Data/Intermediate/...
Analyses/...
Figures/...
```

Do not normally run numbered scripts from inside `Scripts/`.

Good:

```bash
cd ~/Documents/GitHub/BIIGLE-Benthic-Pipeline
./Scripts/01_add_lat_long.sh .
```

Avoid:

```bash
cd ~/Documents/GitHub/BIIGLE-Benthic-Pipeline/Scripts
./01_add_lat_long.sh
```

unless that particular script explicitly documents that behaviour.

# 11. Recommended commit style

A commit should represent a coherent checkpoint.

Good examples:

```text
Add input validation reports
Add latitude and longitude enrichment
Add TAXON_LIST matching
Add VME taxonomy enrichment
Add frame substrate classification
Separate point and VME analytical datasets
Add Shannon diversity analysis
Add square-root Bray-Curtis NMDS
Add environmental PERMANOVA
Update NMDS latitude colour configuration
Document CAP interpretation
```

Avoid vague commit messages such as:

```text
changes
stuff
new version
final
final2
```

Git is the version history. You should not need filenames such as:

```text
analysis_FINAL.R
analysis_FINAL2.R
analysis_REAL_FINAL.R
```

# 16. Generated data and repository size

The current repository is intended to show a worked example. Therefore selected generated datasets, numerical outputs and figures may be committed so another researcher can inspect the result of each step.

However, do not treat Git as unlimited scientific data storage.

In particular:

- original BIIGLE ZIP exports remain local in `Raw/`;
- imagery/video should not be committed to the ordinary repository;
- transient backup/temp files are ignored;
- large future datasets may require Git LFS, a release asset, an institutional repository, Zenodo or another archival data service;
- the folder contract can remain unchanged even if the physical storage strategy changes.

# 17. What .gitignore does

`.gitignore` tells Git which local files should not be versioned.

For this repository it excludes, among other things:

- macOS `.DS_Store` files;
- R history/session files;
- local R/Python caches and virtual environments;
- credentials such as `.Renviron` and `.env`;
- temporary pipeline files;
- safety-backup CSVs created before scripts modify files;
- the contents of `Raw/`.

It does **not** automatically delete anything from your Mac.

It also does not remove a file that was already committed to Git. If a file has already been tracked, it must be explicitly removed from Git tracking if you later decide it should be ignored.

# 18. Important safety checks before committing

Before every commit:

```bash
git status
```

Before a large commit:

```bash
git diff --stat
```

Inspect individual text changes:

```bash
git diff
```

Check that you have not accidentally staged:

- raw ZIP archives;
- huge image/video files;
- passwords/tokens;
- `.Renviron`;
- unnecessary temporary CSV backups;
- duplicate project folders.

If something was staged accidentally but not committed:

```bash
git restore --staged path/to/file
```

This removes it from the staged commit without deleting the local file.

# 20. Pipeline development state

The repository architecture, input validation, lookup tables and existing processing logic are currently being consolidated into the canonical non-destructive folder workflow.

The intended direction is:

```text
Sheets/
  |
  v
numbered processing scripts
  |
  v
Data/Intermediate/
  |
  v
Data/Final/
  |
  +--------------------+
  |                    |
  v                    v
point_annotations.csv  vme_annotations.csv
  |                    |
  v                    v
statistical modules    VME modules
  |                    |
  +---------+----------+
            |
            v
      Analyses/ + Figures/
            |
            v
        README.md
```

The canonical processing wrappers and modular statistical scripts are now defined. The worked-example workflow should be tested in two phases:

```bash
./Scripts/run_processing_pipeline.sh .
```

Review `Analyses/00_Quality_Control/` and the files in `Data/Final/`.

Then:

```bash
Rscript Scripts/install_R_packages.R
./Scripts/run_analysis_pipeline.sh .
```

After inspecting the generated tables and figures, commit the verified outputs to GitHub.

A completely fresh rerun can be performed with:

```bash
./Scripts/run_full_pipeline.sh .
```
